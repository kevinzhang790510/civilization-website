# 章节发布规则

## 三重审批与版本绑定

1. 仅允许 `10_第一部_石之永恒/正文/第001章.md` 这样的正式路径（至少三位数字；不递归扫描，不接受子目录、README、软链接）。未来目录变化必须先审核修改导出器白名单。
2. 文件头必须明确标记定稿及作者批准。只有作者或被明确授权的维护者可以设置。
3. 必须在私有 `publication/chapters.json` 逐章列入，标记“已发布”，并写入完整文件 SHA-256。未列入的文件绝不自动发布。

标记是审批记录，不是作者身份的密码学证明。必须限制 GitHub 中谁能修改定稿文件、发布清单、导出器及工作流。有协作者时通过分支保护/CODEOWNERS/作者审核实施身份约束。未获作者明确确认不能填写 approval 为 true。

## 文件格式（说明模板，当前没有获准章节）

UTF-8，无 BOM，LF 或 CRLF。开头固定：

```text
---
status: 定稿
authorApproved: true
---
# 这里填写作者确认的真实章节标题
```

标题后空一行，再放正式正文段落。正文不能混入批注、设定、草稿、标题、HTML、图片链接或代码块。导出器拒绝明显标记，但无法理解文字的保密级别；作者需要确认整个文件只含获准公开正文。

计算完整文件（含元数据、标题和换行）的 SHA-256：

```sh
python3 -c "import hashlib,pathlib; print(hashlib.sha256(pathlib.Path('10_第一部_石之永恒/正文/第001章.md').read_bytes()).hexdigest())"
```

私有清单字段说明：

```json
{
  "schemaVersion": 1,
  "chapters": [
    {
      "id": "book1-ch001",
      "volume": 1,
      "order": 1,
      "title": "这里填写作者确认的真实章节标题",
      "path": "10_第一部_石之永恒/正文/第001章.md",
      "status": "已发布",
      "authorApproved": true,
      "sha256": "必须替换为文件的真实64位SHA256"
    }
  ]
}
```

这只是字段说明，不是可用发布数据。交付的实际清单是空数组，没有任何章节。

## 更新与撤回

- 改动正文、标题、元数据或换行会改变 SHA-256。必须重新由作者确认并更新清单校验值；不匹配则整次导出失败，不推送部分内容，线上保留上一成功版本。
- 建议同一次提交更新定稿文件及发布清单。只改文件不改批准清单，会阻止发布。
- id 是永久章节标识；order 控制顺序。进度保存 id，减少新增章节导致续读错位。
- 从清单删除章节后，下一次成功同步从当前网站移除它；空清单会清空当前正文列表。
- **撤回不能抹除已公开 Git 历史、下载副本及第三方缓存。** 公开前必须确认，不把公开仓库作为私密预览。
- 新图片需另行批准并扩展公开资源构建白名单，目前不会抓取附件。

私有环境验证命令：

```sh
python3 publication/export_approved.py --private-root . --output /安全临时目录/approved-chapters.json
```

禁止复制未经审核的源目录到公开仓库，禁止把整个小说仓库作为 Pages 构建产物。
